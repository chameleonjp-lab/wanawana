# M8 実機性能確認

## アプリが記録するもの

試合終了時の結果画面に、次の2種類の簡易計測を表示する。

- フレーム間隔: requestAnimationFrameのコールバック間隔を試合中に収集し、P95、P99、最大値、20ms・34ms・67ms・100ms・150msを超えた回数を表示する。
- 入力→次回描画: 入力イベントから次のrequestAnimationFrameまでの経過時間を表示する。複数入力が同じフレームを待つ場合は、最初の入力を1件として扱う。

結果画面の「性能記録をコピー」では、計測値に加えてcommit、ユーザーエージェント、表示領域、倍率、難度、舞台、ロードアウトをJSONでコピーできる。

この値は実機確認用の目安であり、Safariの開発者ツールやOSのフレーム計測に置き換わるものではない。タブ切替・画面ロック・向き変更・描画領域の復旧中は、停止時間をフレーム間隔へ混ぜない。

## 5試合の手順

1. iPhone 17 ProのSafariで公開URLを開き、縦向き、通常表示、低電力モードなしで始める。
2. 毎回同じ条件になるよう、難度・舞台・ロードアウトを記録する。
3. 5試合を連続して最後まで行う。できるだけ罠、弾、爆発、モヤ、連鎖が重なる混雑した局面も作る。
4. 各試合の結果画面で性能値を確認し、性能記録をコピーするかスクリーンショットを保存する。コピーにはcommitと設定も含まれる。
5. 5試合分を並べ、P95/P99/最大値と長いフレームの回数を比較する。

## 合否の目安

iPhone 17 Proの通常表示は、計画書の基準に合わせて次を目安にする。

- フレーム間隔P95が20ms以下
- フレーム間隔P99が34ms以下
- 100ms以上が0件
- 入力→次回描画P95が50ms以下

軽量表示または旧世代端末で確認する場合は、次を目安にする。

- フレーム間隔P95が34ms以下
- フレーム間隔P99が67ms以下
- 150ms以上が0件
- 入力→次回描画P95が100ms以下

画面を離れた、中断から再開した、技術的に無効になった試合は5試合の合格記録へ混ぜない。端末温度、低電力モード、Safariのタブ状態など、測定条件も一緒に残す。

## 残っている確認

この実装で計測欄と記録形式は用意したが、5試合の合否判定と、5試合を通した表示物・画像・AudioNode・イベント登録の増加確認は実機で行う。ここは自動テストやPlaywrightの代替ではなく、iPhoneでの最終確認とする。
