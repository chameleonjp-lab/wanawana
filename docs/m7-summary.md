# M7 端末内戦績

結果が確定した試合だけを、`localStorage` の `wanawana:v1:summary` に1つのJSONとして保存する。tickごとの書き込みは行わない。

保存するのは試合数、勝敗・引き分けの件数、最大連鎖、プレイヤーの罠設置数と解除数である。保存値は `schemaVersion`、整数、範囲、勝敗件数と試合数の関係を検査し、壊れた値・未来版・範囲外値は空の集計へ戻す。

`localStorage` の読込・書込が拒否された場合も、試合は止めずメモリ上の集計だけを更新する。`localStorage.clear()` は使わず、ワナワナ固有のキーだけを扱う。タイトル画面と結果画面には、保存できているかどうかを含めて現在の集計を表示する。

## 対戦記録

結果が確定した試合では、受理済みのプレイヤーとCPUの整数命令をtick順に記録する。記録の先頭にスキーマ版、実装版、ビルド識別子、調整値ハッシュ、面ハッシュ、疑似乱数方式、seed、tickレート、入力エンコード版を置き、0 tickと300 tickごとの状態ハッシュ、および最終ハッシュを保存する。生のDOMイベントや指座標、重要イベントの表示文は再生の正本にしない。

記録はJSONとして結果画面からコピーできる。タイトル画面の「対戦記録を検査する」へ貼り付けると、別の端末で同じ記録を検査できる。読み込み時は型、整数範囲、配列長、2MBの容量上限を検査し、現在の実装版・調整値・面のハッシュが一致しない記録は検証対象にしない。検証ではCPUを再判断せず、記録済みの命令を同じ固定tickへ渡し、最初に異なるチェックポイントを報告する。1試合は11,000 tick、チェックポイントは100件までとし、上限超過や記録失敗の試合はコピー可能な対戦記録を作らない。

## 境界

アカウント同期、ランキング、試合途中の復旧、他ゲームとの共有は扱わない。対戦記録の共有は結果画面からの利用者操作によるコピーに限る。次の試合を開始しても前の結果を二重計上せず、技術的に無効になった試合は勝敗・戦績へ加えない。設定操作からワナワナ固有の保存キーだけを削除できる。
