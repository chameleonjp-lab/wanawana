# M7 CPU難易度バランス監査

CPUの難易度を変更したときに、見えている情報の範囲や固定tickの規則が変わらないことを確認する。勝率だけで難易度を決めず、同じ入力を与えたときの結果、試合時間、連鎖、技術的無効の有無を記録する。

## 固定入力シナリオ

監査用の入力は人間の勝率を再現するものではない。実装変更の比較条件をそろえるために使う。

- **pressure**: プレイヤーがCPUへ近づき、39tickごとに射撃し、45tick以降に180tick間隔でハネ板・ビリビリ盤を置く。
- **hold**: プレイヤーは開始位置から動かず、同じ射撃と罠設置を行う。CPUが罠の共有危険表示へ反応できるかを見る。

各試合はseed、難易度、シナリオ、勝敗、試合tick、最終状態ハッシュ、最大連鎖を保存する。`tests/core/balance.test.ts` は18試合を2回実行し、同じ結果になることと、技術的無効・上限超過がないことを検査する。

## 判断と保留

pressureでは、難易度が上がるほどCPUの勝ちが増え、意図した段階差が出ている。一方、holdでは、むずかしいCPUが固定位置の罠へ対応できず、10試合すべてでプレイヤーに負けた。これは「むずかしいほど常に強い」とは言えない警告である。ただし固定入力は人間の操作を表さないため、この表だけで罠の威力やCPUの反応時間を変更しない。

次の調整では、CPUが共有危険表示を受け取ってから調査・解除を始めるまでの挙動と、罠の設置位置の妥当性を、実際の人間操作で確認する。技術的無効が0件でない場合、または同じ入力のハッシュが一致しない場合は、バランス調整より先に実装を止める。

アカウントの勝率集計やランキングは、この監査へ追加しない。端末内戦績と決定論的な対戦記録を使い、個人を識別せずに再現できる範囲だけを扱う。
